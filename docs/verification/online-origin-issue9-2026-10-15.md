## Reproduced source mechanism

MediaSourceManager tries `localSourceOf` before the online resolver for ordinary HTTP
queue items. OfflineLibrary previously used the store's origin lookup to choose a
saved audio file even when the requested item was the original online video.
OfflineMediaTag then created a synthetic StreamInfo with the HTTP item's URL/type/title
but no video/audio stream lists or related items.

Player listeners consume that tag. VideoDetailFragment accepts metadata with the same
HTTP URL as its currentInfo and replaces the reference; its related/download paths
consume currentInfo. The issue8 local-URI guard cannot classify this sparse HTTP object
as saved metadata. Same-item source retention and listener rebinding can expose it.

No cache-key collision or cache insertion of synthetic local metadata was found.
InfoCache uses service/type/literal URL keys; the queue item identity fields are final.
The regression's original cache stays full while the selected playback tag becomes sparse.
This identifies a source mechanism matching the reported symptoms without claiming the
user's exact installed build or rendered-device reproduction has been verified.

## Change

OfflineLibrary.source now returns null before inventory lookup for identities that are
not explicit `backtube-offline:` URIs. Original online playback therefore follows the
existing metadata/source resolver even when saved audio has the same origin.
The store's origin lookup remains available for inventory/admin uses; OfflineFirst,
cache keys, queue equality, downloader behavior, and stored data formats are unchanged.
No cache purge, migration, user-data reset, or saved-file deletion is needed.

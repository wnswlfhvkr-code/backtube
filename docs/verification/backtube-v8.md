# backtube v8 검증

2026-09-30. 최신 v7 소스에서 곡 선택 후 추가 재생 버튼이 필요한 증상을 재현하고 수정했습니다. 첨부 영상은 구버전이라는 사용자 설명에 따라 증상 참고용으로만 사용했습니다.

## 변경

- 검색·추천·피드·기록·저장한 재생목록에서 곡을 직접 선택하면 정보 로딩 후 즉시 재생합니다. 공유 경로에서 명시적으로 플레이어 재생을 선택하는 경우에도 적용합니다.
- 상세 보기·일반 스트림 인텐트·재시도는 기존 자동재생 정책을 유지합니다. 플레이어 화면 전환은 기존 재생/일시정지를 유지합니다. 외부 플레이어 및 대기열 교체 확인 설정도 유지합니다.
- 화면 로딩 중인 직접 재생 요청만 상태로 저장하고, 실제 재생 인텐트 전달 후 소모합니다.
- 종료된 목록 화면에 늦게 도착하는 설정 알림으로 발생한 크래시를 로컬·원격 목록 공통 경로에서 막았습니다.

## 확인

- 수정 전 동일 네이티브 테스트가 `song selection required an extra play-button press`로 실패했습니다.
- 최종 Debug·계측 테스트·Release 빌드와 릴리스 필수 lint 통과. Checkstyle 보고 0, Kotlin lint 통과. 관련 단위 테스트 63개, 실패/오류 0.
- Android 15 전용 에뮬레이터에서 전체 재생 회귀 `OK (31 tests)`: 프로세스 복원 단계 및 별도 승인된 네트워크 정책 단계 2개 제외, 실제 29개 실행·실패 0. 화면 종료 후 설정 알림 크래시 수정 후 결과입니다.
- 최종 두 목록 가드까지 포함한 빌드에서 직접 선택·인텐트 재생·일시정지 화면 전환·수동 상세 보기, 이어지는 중복 다음곡 테스트, 실제 Wi-Fi 요금제 정책 전환을 별도 실행해 `OK (3 tests)` 확인. 정책은 원래 `none`으로 복원했습니다.
- 합성 메타데이터·생성 WAV만 사용했습니다. 곡 선택 테스트는 자동재생 설정을 Never로 지정하고, 재생 버튼 없이 백그라운드 A→B, 메인 B→C, 명시적 인텐트 C→A가 재생되는지 확인합니다. 가짜 URL의 댓글 추출은 이 테스트에서만 끄고 복원합니다.
- 재생 화면 및 최종 릴리스 홈 화면을 캡처해 확인했습니다. 같은 개인 키의 v1/v2/v3 서명과 zipalign 통과. v7/1021 위에 v8/1022 업데이트 설치 성공, MainActivity `Status: ok`.
- 독립 읽기 전용 검토에서 수동 상세 보기와 Context 인텐트 경로를 보완하고 최종 검토 통과했습니다.

## 범위와 초기 실패 기록

전체 JVM 테스트 최초 실행은 184개 중 백업 가져오기 관련 13개가 실패했습니다. 테스트 리소스 경로의 한글이 `%eb...`로 남아 파일을 찾지 못하는 환경 문제를 XML에서 확인했습니다. 해당 테스트와 백업 코드는 수정하지 않았으며, 전체 JVM 테스트 통과를 주장하지 않습니다.

초기 네트워크 정책 병행 실행은 비요금제 복원 대기 제한에서 실패했으며, 최종 빌드 종료 후 같은 테스트는 통과했습니다. 초기 화면 종료 후 크래시는 logcat의 `BookmarkFragment not attached` 원인을 수정했습니다. 실패 로그도 보존했습니다.

실제 YouTube 네트워크 재생·갤럭시 화면 꺼짐·실제 데이터 절감량은 이번 검증에 포함하지 않았습니다. 원격 CI 결과는 로컬 검증과 별도입니다.

## 곡 종료 후 자동 넘김 재확인

2026-09-30 사용자 추가 요청으로 관련 네이티브 테스트 6개를 새로 실행해 `OK (6 tests)` 확인했습니다. 대기열 및 추천 재생 검증을 보강했으며 앱 실행 코드는 수정하지 않았습니다. 전달한 v8 APK의 해시도 그대로입니다.

- 다음 버튼·끝부분 탐색 없이 4초 WAV를 끝까지 재생했습니다. 자동 대기열 OFF에서도 이미 대기열에 있는 A→B는 바로 재생되며, 마지막 B에서는 멈춥니다.
- 자동 대기열 ON에서는 A→추천 B→추천 C가 각각 끝날 때 이어 재생됩니다. 추천이 없는 C가 끝나면 멈추며 이전 곡으로 돌아가지 않습니다.
- 늦게 도착하는 추천 미리보기가 자동 넘김을 막지 않는지, 중복 다음곡 요청이 한 번만 넘어가는지, ‘현재 곡 끝에서 정지’ 타이머가 자동 넘김보다 우선하는지도 통과했습니다.
- 계측 테스트 APK 빌드·Checkstyle 보고 0. 증거는 `verification/v8-auto-next-build.txt`, `v8-auto-next-runtime.txt`, `v8-auto-next-logcat.txt`입니다. 생성 WAV 및 합성 추천 메타데이터 기준이며 실제 YouTube 추천 추출·휴대폰 재생은 미검증입니다.

마지막 곡 뒤 추천곡까지 계속 들으려면 상세 화면의 **자동 대기열에 추가**를 켜고 한 곡 반복을 해제해야 합니다. 자동 대기열 기본값은 ON이며 업데이트 설치는 기존 설정을 유지합니다.

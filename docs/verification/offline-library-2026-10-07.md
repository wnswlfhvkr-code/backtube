- Routing: no remote lookup for a saved item; no fallback for a missing local-only item; ordinary online fallback when inventory access fails.
- Giga output: shared RandomAccessFile growth budget, seek overwrite and cancellation.
- Real DownloadManager scheduling with mocked transport/storage: Start all respects the offline network policy; repeated capability callbacks preserve a single active mission; a restored shelf queue starts when policy permits.
- Real DownloadMission completion with mocked Android notification/storage: commit before metadata removal; failed commit retains metadata and retry finishes without a download.
- Android generated-WAV tests added through Player: empty InfoCache local playback and timer expiry, plus persisted queue reconstruction with paused playback.

The completion retry test independently failed before changing the completed-mission retry guard. Queue tests isolate actual scheduling from Android transport discovery; they do not claim real Wi-Fi switching coverage.

The API exposed job results, but the cloud proxy returned HTTP 403 when fetching redirected Azure logs/artifacts; the detailed Android assertion could not be recovered from that run.

Follow-up CI reuses each existing KVM emulator, runs the generated-media lifecycle script before the local connected suite, preserves both API results with `fail-fast: false`, and publishes concise test outcomes/failures as check annotations as well as artifacts. No extra emulator job or Windows environment is introduced. The lifecycle's expiry fixture changes a generated item's stored deadline to the past before process termination; this verifies restart enforcement without waiting seven days. It does not simulate Android background expiry scheduling.

The new script is [verify-offline-android.sh](../../scripts/verify-offline-android.sh). It checks instrumentation's textual result because `am instrument` can exit zero after a process crash. A fixture reflection target was corrected to the app Player rather than the imported ExoPlayer interface.

## Product and operational limits

- Shelf playback uses the existing background audio player, including audio from video files. A fullscreen offline video interface is not part of this increment.
- Capacity is fixed at decimal 500 MB and lifetime at seven days. Wi-Fi-only is adjustable. Giga postprocessing scratch space is separate from the managed output budget.
- Expiry prevents new playback when the inventory is accessed; cleanup is lazy. Active readers can finish before physical deletion. There is no exact-time background expiry alarm.
- Local document imports retry by copying from the beginning. Process death leaves an interrupted import. Giga download resumption remains subject to the existing source URL/recovery behavior.
- Tests do not cover real service downloads, DRM, signed URL expiry, actual device low-disk exhaustion, full process-kill playback restoration, Android timeout duration or OEM background restrictions.

## Service support versus implementation capability

YouTube's official Premium offline experience is an application feature described in [YouTube Help](https://support.google.com/youtube/answer/11977233); this patch does not integrate that entitlement or claim a third-party official offline API. [YouTube API Services Developer Policies](https://developers.google.com/youtube/terms/developer-policies), particularly III.E.1, separately restrict downloading/caching audiovisual content by API clients without prior written approval. Those API-specific terms are distinct from the technical behavior of this repository's existing NewPipe extractor. This document is not a legal determination about every source or use.

The implementation supplies local storage/playback infrastructure around the existing pathway; whether a specific source permits saving remains separate from whether its bytes can be stored technically. [Android foreground-service timeout guidance](https://developer.android.com/develop/background-work/services/fgs/timeout) motivates handling `onTimeout` by pausing downloader work and stopping the service. This was compiled, not duration-tested.
